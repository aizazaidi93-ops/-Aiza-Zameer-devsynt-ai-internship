A week spent learning LangChain and LangGraph before touching the orchestrator-agent project. This page summarizes what each concept means, why it exists, and how it fits into the bigger picture.

01

What is LangChain?

Definition

Calling an LLM directly means sending one prompt and getting one plain-text reply back — every single time, the full prompt has to be written from scratch and the response has no guaranteed structure. LangChain is a framework that sits on top of raw API calls and provides reusable building blocks instead: prompt templates (prompts with fill-in-the-blank variables), chains (a prompt template connected to an LLM connected to an output, wired together as one repeatable unit), and easy switching between different LLM providers without rewriting the whole application.

Example

Without LangChain: the full sentence "Tell me about Lahore" has to be retyped every time the topic changes.
With LangChain: a template "Tell me about {city}" is written once — the value in {city} is swapped for "Lahore" or "Karachi" without rewriting the sentence.

Prompt Templates & Output Parsers

Definition

A prompt template is a prompt written once with placeholders — such as {product_name} — so it can be reused with different values instead of being rewritten each time. An output parser solves a separate problem: by default an LLM replies in free-flowing text, which is unreliable for code to work with. An output parser instructs the LLM to reply in a specific structure — most commonly JSON — so the application can read individual fields directly instead of guessing meaning from a paragraph.

Example — Plain vs. Parsed Output

Plain answer: "The phone is good, price is 20000."
Parsed answer: {"price": 20000, "quality": "good"} — code can read the price and quality fields directly instead of scanning a sentence.

Memory & Tool-Calling

Definition

By default, an LLM has no memory — every call is completely independent, and it has no idea what was said earlier in the conversation. Memory means keeping track of the conversation so far and feeding that history back into every new call, so the model can refer to earlier messages. Tool-calling means giving the LLM access to external functions it can choose to use — a calculator, a search function, a database lookup — instead of guessing an answer from what it already knows. The model itself decides when a tool is needed and what to pass into it.

Example — Memory

Message 1: "My name is Ali." Message 2: "What's my name?"
Without memory → "I don't know." With memory → "Ali."

Example — Tool-Calling

Asked "What is 25 × 37?" — instead of guessing, the LLM recognizes it needs precision and calls a calculator tool, which returns 925.

What is LangGraph?

Definition

A chain follows a fixed sequence of steps, always in the same order — Step 1, then Step 2, then Step 3, no matter what happens. An agent can look at the current situation and decide what to do next — skipping a step, repeating one, or choosing between different paths. LangGraph is the framework that lets these decision-making systems be built as a graph instead of a straight line. Its core building blocks are: a node (one step in the graph), an edge (a connection that shows what happens next), a conditional edge (a decision point based on a node's result), and state (the data that gets passed along and updated as it moves through the graph).

Orchestrator Agents

Definition

An orchestrator agent receives a task, figures out what needs to happen, and routes it to the right specialized agent(s) — it usually doesn't do the actual work itself. It behaves like a manager: it doesn't clean the data or write the report itself, it decides who should. This is exactly the pattern the upcoming project will use — an orchestrator agent that receives raw data and decides which specialized agent handles it next, using LangGraph's node and conditional-edge structure to route between them.

Example

Task: "Clean this data and write a report."
The orchestrator routes it → Data Cleaning Agent first, then passes the cleaned result to → Report Writing Agent.

What I Learned

This week I learned that LangChain provides reusable components — prompt templates, chains, and output parsers — for working with LLMs, instead of writing every API call from scratch. I also learned that by default an LLM has no memory and no access to tools, and that both have to be deliberately added. Most importantly, I learned the difference between a chain (a fixed sequence) and a graph (a decision-making structure) — which is why LangGraph, with its nodes, edges, state, and conditional edges, is needed for the orchestrator-agent project coming up next.
